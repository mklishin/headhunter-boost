## Как сообщить об ошибке

1. Убедитесь, что такой issue ещё нет в [списке задач](https://github.com/mklishin/headhunter-boost/issues)
2. Создайте новый issue и включите:
   - Версию скрипта (видна в заголовке панели, например `v6.1`)
   - Браузер и версию Tampermonkey
   - Полный текст из журнала — нажмите **📋 Копировать** в панели
   - Что ожидалось и что случилось

**Если перестали находиться кнопки или заголовки вакансий** — скорее всего, hh.ru обновил разметку. Это наиболее частая причина поломок. Приложите значение `data-qa` из текущего исходного кода страницы (DevTools → Elements → найдите кнопку «Откликнуться» → посмотрите атрибут `data-qa`).

## Как предложить изменение

1. Сделайте fork репозитория
2. Создайте ветку:
   ```bash
   git checkout -b fix/краткое-описание
   # или
   git checkout -b feature/краткое-описание
   ```
3. Внесите изменения в `headhunter-boost.user.js`
4. Проверьте синтаксис:
   ```bash
   node --check headhunter-boost.user.js
   ```
5. Протестируйте вживую на странице поиска hh.ru
6. Обновите `CHANGELOG.md`
7. Откройте Pull Request

## Стиль кода

- Один файл `.user.js`, без системы сборки и внешних зависимостей
- Комментарии в коде — на английском
- `const` по умолчанию; `let` только там, где переменная переназначается
- Все задержки — через `sleep()`, без вложенных `setTimeout` без причины
- Любое взаимодействие с DOM — через `humanInteract()`, не прямой `.click()`
- Добавляя новую GM-переменную, отразите её в блоке `// GM keys:` в шапке кода и проверьте, входит ли она в `clearSession()` или нет, и почему
